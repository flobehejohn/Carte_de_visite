9. Design recommande pour orbDebug.ts
[R] Design cible V1 (sobre, robuste):
- centraliser decision de visibilite (verbose/audit/warn/error),
- centraliser throttle/sampling,
- normaliser prefix/tags,
- interdire la logique de niveau dans les modules appelants.

[R] Principes:
- `orbError` et `orbWarn` ne cachent jamais les anomalies critiques,
- `orbLog` est silencieux par defaut hors verbose/audit,
- audit certifiant separe du verbose humain (2 axes distincts),
- signature API stable pour migration progressive sans casser runtime/tests.

10. Emplacement recommande et justification
[R] Emplacement recommande: `src/shared/debug/orbDebug.ts`

Justification:
- couvre le noyau scene (Oracle3DScene + modules scene),
- reutilisable par services (`zarathoustraService`, `geminiClient`) sans dupliquer un second utilitaire,
- evite une migration ulterieure de `src/scene/utils` vers `shared` quand scope s etendra.

[H] Si l equipe veut une V1 ultra limitee au runtime 3D uniquement, `src/scene/utils/orbDebug.ts` reste possible, mais cree une dette de relocalisation probable.

11. API minimale recommandee
[R] API V1 minimale:
- `isOrbVerbose(): boolean`
- `orbLog(message: string, tags?: OrbTags, opts?: OrbLogOpts): void`
- `orbWarn(message: string, tags?: OrbTags, opts?: OrbLogOpts): void`
- `orbError(message: string, tags?: OrbTags, opts?: OrbLogOpts): void`

[R] Types minimaux proposes:
- `OrbTags`: `{ subsystem: string; stage?: number; seed?: string; profile?: string; event?: string }`
- `OrbLogOpts`: `{ audit?: boolean; throttleMs?: number; throttleKey?: string; neverHide?: boolean }`

[R] V1.1 optionnelle (pas en V1 si scope strict):
- `isOrbAuditMode(): boolean`
- `orbMetric(name: string, value: number, tags?: OrbTags): void`

12. Politique de visibilite par niveau
[R] Politique cible:
- `orbError`: toujours visible
- `orbWarn`: visible par defaut, sauf cas explicitement non-critiques (eviter sur-usage)
- `orbLog`: visible uniquement si `isOrbVerbose()` ou `opts.audit === true && isOrbAuditMode()`
- `neverHide`: force emission meme si verbose/audit off (cas critiques)

[R] Convention prefixage:
- format unique: `[ORB][<subsystem>][<level>] <message>`
- tags serialises de facon compacte (pas d objets massifs en continu).

13. Politique DEV / TEST / PROD
[R] DEV:
- `warn/error` visibles,
- `info` via verbose explicite,
- mode audit activable separement du verbose.

[R] TEST:
- par defaut limiter `info` (eviter bruit CI),
- mode audit activable pour diagnostics ciblés,
- `warn/error` critiques conserves.

[R] PROD:
- `warn/error` visibles (anomalies),
- `info` off par defaut,
- aucun log periodique de confort.

[R] Reponse explicite aux questions de gouvernance:
- separer verbose humain et audit certification: OUI (obligatoire).
- conserver certains `warn` hors verbose: OUI (critical runtime / fallback).
- interdire futur `console.*` direct dans modules cibles: OUI (sauf orbDebug).
- prevoir garde-fou lint/grep/test: OUI (phase validation CI).

14. Risques de regression
[L] Risque principal non fonctionnel:
- perte de signal critique si mauvaise classification (warn -> log masquable).
[L] Risque secondaire:
- rupture de tests d audit si la migration touche par erreur le bridge (API `__ORB_AUDIT__`).
[L] Risque technique:
- wrapper logger mal implemente peut throw et impacter hot path.

[R] Mitigations:
- migration en deux passes (prioritaires puis coherence),
- etiqueter explicitement `neverHide` pour cas critiques,
- aucun changement de semantics runtime dans la meme PR que le logging.
